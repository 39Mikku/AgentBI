# AgentBI 智能体后端服务开发文档

## 1. 项目背景与架构概览

本项目旨在将原本零散的脚本和工具代码，重构并沉淀为一个标准的、面向企业的 **FastAPI 智能体微服务架构 (`AgentBI`)**。项目核心实现了以大模型为大脑的自动化业务流，包括且不限于：用户信息的智能查询、动态验证码生成、以及自动化邮件发送。

### 1.1 目录结构
重构后的项目遵循标准的 Python 工程化规范：
```text
AgentBI/
 ├── .env                 # 环境变量配置文件（数据库、邮箱授权码等）
 ├── main.py              # FastAPI 服务程序主入口
 └── src/
     ├── agents/          # 核心智能体业务逻辑 (例如：login_agent)
     ├── api/             # FastAPI 聚合路由
     ├── logging/         # 统一日志记录器
     ├── models/          # LLM 实例化模块
     ├── schemas/         # Pydantic 强类型校验模型（入参/出参约束）
     └── tools/           # 大模型可调用的本地工具集（DB查询、邮件发送等）
```

## 2. 核心模块开发复盘

### 2.1 基础设施搭建 (main.py 与 Logging)
*   **FastAPI 入口 (`main.py`)**：完成了应用的实例化与 `uvicorn` 启动端点，为后续 `api/` 路由的挂载打好了地基。
*   **企业级日志 (`logging.py`)**：
    *   引入 `RotatingFileHandler` 实现了按大小自动切割轮换的日志记录机制。
    *   **避坑指南**：在开发日志工厂方法时，必须使用 `@classmethod` 而不是 `@staticmethod`，否则类方法的首个 `cls` 参数会被传入的字符串名覆盖，导致 `AttributeError: 'str' object has no attribute` 报错。

### 2.2 工具层的剥离与重构 (tools/)
*   将历史遗留的 `mongo_query_tool.py` 与 `send_email_tool.py` 移入专用的 `tools` 包中。
*   全面清理了旧有的、绝对路径耦合的包引用（将原本 `code.xxx` 全面替换为规范的 `AgentBI.src.xxx`）。
*   工具方法均使用 LangChain 的 `@tool` 装饰器，并绑定 `args_schema` 提供给 LLM 使用。

### 2.3 数据结构的强类型约束 (schemas/)
为了避免大模型“放飞自我”，开发了专门的 Schema 层用于双向约束：
*   **入参约束 (`EmailSchema`, `MongoSchema`)**：严格定义大模型在调用工具时，必须生成的参数及其类型。
*   **出参约束 (`EmailResp`)**：在 `create_agent` 的 `response_format` 中强制绑定该模型。要求模型不论如何推导，最终反馈给前端的数据必须是极其严格的 JSON 结构：
    ```json
    {
      "code": 200,
      "msg": "验证码发送成功！",
      "data": "123456"
    }
    ```

### 2.4 面向对象智能体开发 (agents/login_agent.py)
*   **OOP重构**：把离散的调用写成 `LoginAgent` 类，统一管理生命周期。在 `__init__` 中完成日志初始化、大模型加载及工具装配。
*   **Prompt 调优（核心心得）**：
    *   **业务逻辑透传胜于语法教学**：大模型本身极度聪明，懂得什么是 JSON。在写 Prompt 时，**绝对不要去教它“如何写 JSON”**，而是应该清晰地告诉它**业务的底层映射表**。
    *   *正确的做法*：“当需要查询邮箱时，请去 `users` 集合中根据 `username` 字段进行查询。”（模型领悟后会自动构造正确的 JSON 查询体）。
    *   **参数净化**：初始化模型实例 `LLMModel.load_model_once()` 时，避免传入多余的干扰参数（如 `thinking="disabled"`），给模型最大的原生发挥空间。

### 2.5 智能体记忆系统强化 (参考之前的 10-内存记忆功能.py)
在独立的记忆对话场景下，我们复盘了上下文持久化（Context Persistence）的正确用法：
1.  **挂载 Checkpointer**：引入 `langgraph.checkpoint.memory.MemorySaver`。
2.  **绑定 Thread ID**：在 `agent.invoke` 时，必须传入 `config={"configurable": {"thread_id": "会话标识"}}`，这是大模型进行跨轮次上下文记忆的核心线索。
