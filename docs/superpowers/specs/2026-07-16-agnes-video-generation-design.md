# Agnes 视频生成原子工具设计

## 目标

在 Studio 主助手中新增 `tool.video_generation`。主模型只负责根据用户要求生成提示词，并选择画幅和时长；后端负责提交 Agnes Video v2.0、持久化任务、自动轮询、下载成片和更新可播放卡片。

## 固定边界

- 工具名：`generate_video`。
- 固定模型：`agnes-video-v2.0`。
- 固定文生视频，不暴露图片、关键帧、负面提示词、种子或推理步数。
- 工具参数只有 `prompt`、`aspect_ratio`、`duration_seconds`。
- 支持画幅：`16:9`、`9:16`、`1:1`、`4:3`、`3:4`。
- 支持时长：`3`、`5`、`10`、`18` 秒。
- 固定 24 FPS，时长依次映射为 `81`、`121`、`241`、`441` 帧。
- 能力配置保存默认画幅和默认时长；模型可按用户明确要求覆盖。
- API Key 只从 `AGNES_API_KEY` 环境变量读取。
- 不自动暂存或提交 Git。

## 架构

`AgnesVideoClient` 只封装创建任务、查询状态和下载 MP4。`VideoGenerationService` 创建 SQLite 任务并启动后台协程；工具创建任务后立即返回 `video.generation` 卡片，不等待成片。前端卡片轮询项目自己的任务状态接口，完成后使用本地附件 URL 播放和下载。

SQLite 新增 `video_generation_jobs` 表，记录用户、会话、消息、请求快照、Agnes `video_id`、状态、进度、错误、成片资源 ID 和时间。服务启动时将遗留的 `queued`、`in_progress` 任务恢复为后台轮询，确保刷新、切换会话或后端重启不会丢失任务。

## 数据流

1. 主模型调用 `generate_video(prompt, aspect_ratio, duration_seconds)`。
2. 服务保存本地任务并向 Agnes 创建任务。
3. 工具立即返回紧凑 JSON 和 `video.generation` 卡片，主回复可以结束。
4. 后台轮询 `video_id`，持续写入状态和进度。
5. `completed` 后下载 MP4，保存到本地生成物目录，注册 `video` 附件并绑定原助手消息。
6. 前端卡片通过任务查询接口更新，完成后渲染原生视频播放器与下载入口。

## 错误处理

- 缺少 API Key 时创建任务立即失败并返回明确错误。
- Agnes 400/401/404 作为不可重试错误；500/503 和网络错误使用有限退避重试。
- 后台任务失败后保留错误信息，卡片停止轮询并提供可读状态。
- MP4 下载失败视为任务失败，不使用可能过期的上游 URL 作为最终资产。
