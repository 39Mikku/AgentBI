# 工具调用详情折叠设计

## 目标

降低工具返回长文本或 JSON 对聊天时间线的视觉干扰，同时保留完整结果供用户按需查看。

## 交互规则

- `tool_started` 事件保持紧凑单行，显示“工具名 · 执行中”，不提供空内容展开区。
- `tool_finished` 事件默认折叠。
- 完成态折叠标题显示“工具名 · 已完成”，能够识别列表结果时追加数量，例如“3 项结果”。
- 点击完成态标题后展开完整工具返回内容。
- JSON 内容使用缩进格式展示；普通文本保持原文并保留换行。
- `card` 事件不参与折叠，搜索结果卡片仍按当前时间线位置完整展示。
- 正文、推理摘要、工具事件和卡片的既有时间线顺序不改变。

## 组件边界

新增独立的工具事件展示组件，由它负责：

1. 判断执行中与完成状态。
2. 从工具结果中提取可选的结果数量摘要。
3. 格式化 JSON 或普通文本。
4. 管理原生 `details/summary` 折叠交互与样式。

`ChatView` 只负责在时间线和旧消息兼容分支中调用该组件。`TimelineCard` 继续独立渲染，不嵌入折叠组件。

## 异常与兼容

- 空结果显示“已完成”，展开区省略。
- 无法解析的 JSON 按普通文本展示，不抛出渲染错误。
- 历史消息中的 `tool_events` 与新时间线中的工具事件使用同一组件。
- 流式阶段先显示执行中状态；收到完成事件后显示一个独立的完成态折叠块，保持服务端事件原始顺序。

## 验证

- 单元测试覆盖 JSON 格式化、结果数量提取和普通文本回退。
- 静态组件测试确认完成态使用默认关闭的 `details`，卡片渲染分支未被包进工具折叠块。
- 运行前端类型检查与生产构建。
- 在 Chrome 中验证默认折叠、手动展开以及卡片始终可见。
