# Live 角色、会话与记忆系统设计

## 目标

把现有单次 Qwen-Audio Realtime 通话页升级为可持续使用的 Live 模块：用户可以创建和切换角色，每个角色拥有独立的语音会话列表、提示词、音色、头像和长期记忆；继续已有会话时恢复可配置长度的历史上下文，新建会话不注入历史。

Live 继续保持独立于 Studio 的 Agent、Tool、RAG 和消息 DAG。公共模型路由与 SQLite 基础设施可以复用，但 Live 不复用 Studio 的助手、线程、消息或记忆记录。

## 配置边界

### 用户级公共配置

`live_preferences` 只保存所有 Live 角色共享的通话策略：

- `model`：`qwen-audio-3.0-realtime-flash` 或 `qwen-audio-3.0-realtime-plus`。
- `history_context_turns`：继续旧会话时注入的历史 QA 轮数。UI 使用非线性滑块，取值为 1 至 50，最右端表示全部历史；数据库使用 `0` 表示全部。
- `max_history_turns`：百炼在当前 WebSocket 会话内用于推理的历史 QA 轮数，取值为 1 至 50，默认 20。

新建会话始终不注入历史，`history_context_turns` 只影响继续已有会话。

### 角色级配置

`live_roles` 保存：

- 角色名称。
- 系统提示词。
- 音色 ID。内置音色和后续声音复刻音色使用同一字符串字段。
- 可选的持久化头像 Data URL。
- 跨会话记忆开关。
- 默认角色标记。

系统必须为每个用户确保存在一个默认 Live 角色。现有 `live_preferences` 中的 `instructions` 与 `voice` 在首次创建默认角色时作为初始值迁入角色配置，之后不再作为公共配置编辑。

### 角色长期记忆

`live_role_memories` 按 `user_id + role_id` 保存：

- 可编辑的记忆正文。
- 最近一次纳入记忆更新的消息标记。
- 更新时间。

关闭角色记忆不会删除正文或移动消息标记，只会停止上下文注入和通话结束后的自动更新。重新开启后继续使用原有记忆。清空记忆必须是独立的显式操作。

## Live 会话与消息

### 会话

`live_threads` 保存：

- `id`、`user_id`、`role_id`。
- 标题。
- 创建时间、更新时间和最后消息时间。

会话列表必须按当前角色隔离，并按最后消息时间倒序。用户可以新建、选择、重命名和删除会话。新会话初始标题为“新语音会话”，收到第一条最终用户转写后，用其前 30 个字符生成本地标题，不调用标题模型。

切换角色时恢复该角色上次选择的会话；没有历史会话时保留空选中状态。通话进行中禁止切换角色、切换会话、删除会话或修改会影响连接的配置。

### 消息

`live_messages` 保存：

- `id`、`thread_id`、`user_id`、`role_id`。
- 百炼 `item_id`。
- `role`：`user` 或 `assistant`。
- 最终文本。
- `status`：`complete` 或 `interrupted`。
- 创建时间和更新时间。

流式 delta 只保存在前端状态中。收到最终转写事件时才持久化完整消息。被用户打断的模型回复保留当前已收到文本并标记为 `interrupted`，用于用户浏览，但不在后续会话恢复时重新注入模型。

不同角色的会话和消息完全隔离。

## 建立实时会话的数据流

前端发送的 `session.start` 包含 `role_id`、可选的 `thread_id`，以及公共模型配置。后端必须以数据库中的角色和公共配置为准，不能信任前端直接传入的提示词或音色。

建立新百炼 WebSocket 后按以下顺序执行：

1. 发送 `session.update`，配置公共模型策略、角色音色、角色系统提示词、`smart_turn` 和 `max_history_turns`。
2. 若角色记忆已开启且记忆正文非空，将其作为独立 `<role_memory>` 段追加到本次 `session.update.session.instructions`。
3. 如果 `thread_id` 指向已有会话，读取最近 `history_context_turns` 轮或全部已完成消息，按原顺序组成 `<conversation_history>` 段追加到同一 instructions；跳过 `interrupted` 消息。
4. 向前端发送 `session.ready`，此后才允许前端发送麦克风 PCM。

新建会话不执行第 3 步。百炼当前的 `conversation.item.create` 仅支持 `function_call_output`，不能用于回放普通消息，因此记忆和历史必须随会话初始化提示词一次性提交。初始化失败时终止本次连接并返回稳定错误，避免用户在缺少预期上下文的情况下继续通话。

## 消息持久化与通话结束

WebSocket 路由维护本次连接关联的用户、角色和会话。最终用户转写和最终模型字幕到达时立即写入 `live_messages`，并通过规范化事件把数据库消息 ID 返回前端。前端刷新或切换会话时从 REST API 重新加载已保存消息。

通话结束、浏览器主动关闭或上游结束时，后端都应完成连接清理。只要本次通话产生了新的完整消息，就可以进入结束后维护流程；客户端挂断响应不等待记忆模型。

## 通话结束后的角色记忆更新

角色记忆开启且本次通话产生新完整消息时，后端在连接结束后启动一次后台更新：

1. 读取已有角色记忆。
2. 读取本次通话中尚未被记忆标记覆盖的完整消息。
3. 通过现有 `ModelTaskService` 的 `memory` 模型路由发送“已有记忆 + 新通话内容”。
4. 要求模型保留稳定偏好、人物关系、长期目标、承诺和重要事实，合并重复内容，移除临时闲聊。
5. 成功后原子保存新记忆正文和最后消息标记。

没有配置记忆模型、模型调用失败或返回空内容时，保留原有记忆和标记，不影响通话记录。一次通话最多触发一次记忆模型调用，不在每轮对话后分析。

角色管理提供查看、编辑、保存、清空和立即重新提炼记忆的操作。“立即重新提炼”只在记忆开关已开启且记忆模型可用时执行。

## API

公共配置：

- `GET /live/preferences?user_id=...`
- `PUT /live/preferences?user_id=...`

角色：

- `GET /live/roles?user_id=...`
- `POST /live/roles`
- `PUT /live/roles/{role_id}?user_id=...`
- `DELETE /live/roles/{role_id}?user_id=...`
- `GET /live/roles/{role_id}/memory?user_id=...`
- `PUT /live/roles/{role_id}/memory?user_id=...`
- `DELETE /live/roles/{role_id}/memory?user_id=...`
- `POST /live/roles/{role_id}/memory/refresh?user_id=...`

会话与消息：

- `GET /live/conversations?user_id=...&role_id=...`
- `POST /live/conversations`
- `PUT /live/conversations/{conversation_id}?user_id=...`
- `DELETE /live/conversations/{conversation_id}?user_id=...`
- `GET /live/conversations/{conversation_id}/messages?user_id=...`

实时连接：

- `WS /live/ws?user_id=...`

所有读取、更新和删除操作必须同时校验 `user_id` 与资源归属。项目当前不增加登录鉴权机制。

## 前端交互与视觉

Live 左侧栏改为角色与会话导航：

- 顶部保留 Studio / Live 模式切换。
- 当前角色入口展示头像、名称和音色，可打开角色选择器或角色管理。
- 新建语音会话按钮。
- 当前角色的会话列表，支持选中、重命名和删除。
- 底部保留用户信息和公共通话配置入口。

设置抽屉拆分为“通话配置”和“角色配置”：

- 通话配置：Flash / Plus、历史上下文长度、`max_history_turns`。
- 角色配置：名称、头像、系统提示词、内置音色选择、自定义音色 ID、记忆开关和记忆编辑器。
- 自定义音色 ID 非空时优先使用；选择内置音色会清空自定义值。

中央圆环的核心改为角色头像。无头像时显示角色名称缩写。旋转轨道、波形、状态光晕位于头像外层；聆听、思考、说话和静音状态通过外层动画表达，不给头像叠加大面积遮罩。

字幕面板显示选中会话的持久化历史消息，并在通话时把流式临时消息追加在末尾。最终事件到达后用服务端返回的持久化消息替换临时项，避免重复。

## 错误处理

- 角色、会话不存在或不属于用户时返回 404。
- 默认角色不可删除；存在进行中通话时前端禁用破坏性操作。
- 自定义音色由百炼最终校验。上游拒绝时转换为不包含凭证和业务空间信息的稳定错误。
- 历史注入、记忆注入或百炼连接失败时，不把前端置于可发送音频状态。
- 消息持久化失败时终止连接，避免页面字幕与数据库历史长期分叉。
- 记忆后台维护失败只记录安全日志，不能改变已经保存的通话状态。

## 测试与验收

后端测试覆盖：

- 公共配置默认值、范围校验和用户隔离。
- 默认角色创建、角色 CRUD、头像和自定义音色持久化。
- 角色会话隔离、重命名、删除和消息顺序。
- 新会话不注入历史。
- 继续会话按非线性滑块解析后的轮数注入，全部模式完整注入，并跳过打断消息。
- 注入顺序固定为 session 配置、角色记忆、历史消息、ready。
- 最终转写持久化，流式 delta 不落库。
- 通话结束后最多触发一次记忆更新；关闭开关不注入、不更新且不清空。
- 缺少记忆模型或更新失败时保留旧记忆。

前端测试覆盖：

- 角色切换后只加载对应会话并恢复上次选中项。
- 新建会话启动时不携带历史会话 ID，继续会话携带选中 ID。
- 公共配置和角色配置分别保存。
- 历史上下文非线性滑块的数值映射与“全部”状态。
- 自定义音色优先级和内置音色切换。
- 最终服务端消息替换流式临时项，不产生重复。
- 通话中角色、会话和关键配置不可切换。
- 角色头像在圆环核心中正确显示，无头像时显示回退缩写。

完整验收要求后端全套测试、前端单元测试、TypeScript 类型检查和生产构建全部通过。真实浏览器测试必须使用 Chrome，并在用户已登录时验证角色切换、会话恢复、历史注入、头像展示和通话结束后的记忆状态。
