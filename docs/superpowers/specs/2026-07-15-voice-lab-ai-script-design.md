# Voice Lab AI 文案生成设计

日期：2026-07-15

## 目标

在 Voice Lab 的朗读文本编辑区增加一个轻量文案生成入口。用户输入文案要求，系统复用其当前 Studio 对话模型生成可直接朗读的纯正文，并覆盖现有朗读文本。

## 交互

- 在 `MASTER SCRIPT` 编辑区上方增加单行“AI 文案要求”输入框和“生成文案”按钮。
- 文案要求最长 4000 字符；为空时不能生成。
- 生成期间按钮显示加载状态并禁止重复请求，原朗读文本保持不变。
- 成功后直接覆盖朗读文本框，不提供追加、版本或撤销功能。
- 失败时保留原朗读文本，并在编辑区附近展示错误。
- 文案要求和生成结果不额外持久化。

## 模型调用

- 新增 `POST /toolbox/tts/script/generate`。
- 请求包含 `user_id` 和 `instruction`；响应包含 `text`、`provider_name` 和 `model`。
- 后端读取该用户的 `chat_preferences`，解析其当前对话提供商、模型和温度。
- 如果偏好中没有模型，则使用提供商的默认模型；缺少提供商或模型时返回明确的 400 错误。
- 使用 OpenAI 兼容的非流式 `chat.completions.create`，不创建会话、不写消息、不注入助手、记忆、工具或运行时上下文。
- 复用当前对话温度；不在 Voice Lab 增加模型或温度控件。

## 固定系统提示词

模型必须根据用户要求直接输出最终可朗读正文：

- 不输出标题、解释、分析、Markdown、代码块或外层引号。
- 不添加“以下是”“好的”等开场说明。
- 保持自然口语与适合朗读的标点。
- 遵守用户明确给出的语言、语气、字数、角色和内容要求。
- 最终响应只包含正文。

返回内容去除首尾空白；空响应视为失败。超过 Voice Lab 10000 字符上限时截断到 10000 字符，保证可直接写入编辑器。

## 代码边界

- 在 `ModelTaskService` 增加按对话偏好解析并完成一次文本调用的方法，供 Voice Lab 复用。
- TTS API 只负责参数验证、错误映射和返回结果，不复制供应商客户端逻辑。
- 前端扩展现有 `toolbox-tts` 类型和 API，不新建独立页面或模型配置。

## 测试

- 后端测试覆盖：复用对话偏好、提供商默认模型回退、温度透传、固定提示词、空响应、缺少配置和 10000 字符截断。
- API 测试覆盖成功返回和配置/供应商错误映射。
- 前端测试覆盖生成成功覆盖文本、失败保留文本所依赖的纯状态函数。
- 完整后端测试、前端测试和生产构建通过后，使用 Chrome 插件检查 Voice Lab 的输入、加载、错误与覆盖交互；不在视觉验收中发起真实模型调用。
