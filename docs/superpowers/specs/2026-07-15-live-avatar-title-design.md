# Live 无头像声场与通话标题生成设计

## 目标

Live 角色未配置头像时，中心声场不再显示角色名称或缩写，只展示圆环、波形与状态动效；配置头像后才在中心圆显示头像。Live 会话不再用首条用户转写直接改名，而是在一次通话结束后复用 Studio 的 `title` 模型路由异步生成标题。

## 数据与行为

- 新会话初始标题保持 `新语音会话`。
- 用户最终转写写入 SQLite 时只更新会话时间，不修改标题。
- 通话结束后，如果本次产生了新的完整消息、会话仍为默认标题，并且会话中至少有一条完整用户消息与一条完整助手消息，则调用 `ModelTaskService.complete(user_id, "title", ...)`。
- 标题模型使用当前会话最早的完整一轮转写作为命名材料，输出清理首尾引号和句末标点，并限制为 60 个字符。
- 标题模型未配置、返回空内容或调用失败时保留默认标题，不影响 WebSocket 关闭和角色记忆维护。
- 标题任务与角色记忆任务在 WebSocket 结束后分别调度，互不阻塞。
- 前端结束通话后重新读取消息与会话列表；若标题仍为默认值，则执行有次数上限、命中即停的短轮询，从 SQLite 获取异步生成的最终标题。

## 前端呈现

- `LiveAvatarCore` 的 `avatar` 为空时不渲染任何文字节点，中心仍保留纯声场底纹与动态波形。
- 角色菜单、角色管理、记忆页等小头像仍可使用名称缩写，只有主声场中心不显示缩写。

## 验证

- 后端测试覆盖首条消息不改名、符合条件时生成标题、缺少标题模型时保留默认标题、非默认标题不重复生成。
- 前端测试覆盖中心组件无头像时没有角色名或缩写。
- 运行后端全量测试、前端单测、类型检查和生产构建。
